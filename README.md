# Onda

macOS menu bar radio player. Tauri v2 + Rust core. See `ONDA.md` for the project document.

## Status: M1 — scaffold + audio engine

Nothing in this milestone touches the tray or the real UI; `src/App.tsx` is a test bench.

## Prerequisites (macOS, Apple Silicon)

- Rust ≥ 1.85 via rustup (`rustup update stable`)
- Node ≥ 20
- Xcode Command Line Tools (`xcode-select --install`)

## First run

```sh
npm install
cd src-tauri && cargo test --workspace      # runs EQ/ICY/ring tests AND regenerates src/bindings/*.ts (ts-rs)
cd .. && npm run tauri dev
```

The scaffold was written against the crate sources but has not been compiled yet — expect
to fix a handful of type/borrow errors on the first `cargo check`. Report them back; they
are part of the exercise.

`src-tauri/icons/icon.png` is a 1×1 placeholder. Before the first `tauri build`, generate a
real set with `npm run tauri icon path/to/1024.png`.

## M1 exit criteria

1. Play an MP3 and an AAC stream from the bench; hear audio; `playback:stream_info` arrives.
2. ICY titles update in the "Now" line on stations that send them.
3. Pull the network: state goes `buffering` → `reconnecting (n)` → `playing` when it returns,
   or `error [network]` after 5 attempts (1+2+4+8+16 s).
4. EQ sliders audibly change the sound; `cargo test -p onda-audio` passes.
5. Switching stations silences the old one immediately.

## Layout

```
src/                     React bench (renderer only). src/api.ts is the sole Rust boundary.
src/bindings/            TypeScript types generated from Rust by ts-rs (checked in, regenerated by cargo test)
src-tauri/src/           Tauri shell: commands + event forwarding. No logic.
src-tauri/crates/onda-audio/
  engine.rs              Engine thread (device, Player, tokio) + per-session decode thread
  stream.rs              HTTP open via stream-download; ICY headers
  icy.rs                 In-band ICY metadata stripping
  ring.rs                rtrb ring buffer → rodio Source (never blocks the audio callback)
  eq.rs                  10-band biquad peaking EQ as a rodio Source adapter
  reconnect.rs           Backoff policy
  types.rs               IPC types (ts-rs exported)
```

## Known limitations (M1)

- Shoutcast v1 servers that answer `ICY 200 OK` instead of `HTTP/1.x` are rejected by hyper
  and surface as `error [http]`. radio-browser's `url_resolved` is usually the Icecast/HTTP
  endpoint, so this is rare; measure at M3.
- Pause holds the buffered audio; a long pause is likely to end in a server timeout, which
  the reconnect path handles. "Rejoin live on resume" is M5 polish.
- Sample-rate/channel changes mid-stream (rare on radio) are handled by the EQ adapter but
  not by the ring buffer; the stream restarts via the reconnect path if the decoder ends.
